# Jahgenda stickers – print files

Production files for story #19 (promo stickers, see `design/promo-plan.md`). Everything in this folder is
generated by `scripts/make_stickers.py` – edit the script (or its options), run `make stickers`, commit the
result. Do not hand-edit the SVGs or PDFs.

## Files

| File | What it is | Use |
|---|---|---|
| `sticker-round-50.svg` | Master artwork, round ø 50 mm, 3 mm bleed → 56 × 56 mm canvas, `viewBox` in millimetres | Source of truth, open in Inkscape/Illustrator if a designer needs to tweak |
| `sticker-square-50.svg` | Same for the square 50 × 50 mm sticker | ″ |
| `sticker-round-50.pdf` | Print PDF, one page = 56.13 × 56.13 mm (see *Page size*), all text as vector outlines | **Upload to the printer** |
| `sticker-square-50.pdf` | ″ | ″ |
| `sheet-a4.pdf` | A4 test sheet: 15 stickers (8 round, 7 square) at true size with cut line and a 100 mm scale bar | Home-printer test, phone QR test |
| `preview-round-50.png`, `preview-square-50.png` | 600 px screen previews (what the PDF looks like) | Chat / review with Seraina |
| `qr-jahgenda.txt` | The QR matrix as text (`#` = dark module) | Cache when `segno` is missing; eyeball comparison |

Layout (both stickers): dark background `#14110e`, the logo from `img/logo/jahgenda.svg` (shapes inlined),
the wordmark **Jahgenda** ("Jah" cream, "genda" gold), QR code to `https://jahgenda.ch` on a white
quiet-zone box, `jahgenda.ch` in gold, one slogan line, and the tricolour – as an outer ring on the round
sticker (1.2 mm visible after the cut) and as a bottom stripe red | gold | green on the square one
(2.5 mm visible).

Technical specs:

- **Trim** 50 mm, **bleed** 3 mm on every side (canvas 56 mm), **safety margin** 3 mm inside the trim
  (nothing important closer than 3 mm to the cut; the ring/stripe deliberately run into the bleed).
- **QR code**: version 2, error correction **Q** (25 %), 25 × 25 modules, **0.80 mm per module,
  symbol 20 × 20 mm**, 4-module (3.2 mm) white quiet zone → 26.4 mm white box. Modules are pure black
  `#000000` so the printer puts them on the K plate only (no registration blur on 0.8 mm modules).
  The URL is encoded as `https://jahgenda.ch` – shortest possible, so the modules stay big.
- **Cut line**: group `id="cutline"`, magenta `#ff00ff`, 0.25 mm, dashed, in both SVGs and PDFs. It is a
  plain vector line, *not* a spot colour named "CutContour" (Chrome cannot write spot colours). Printers with a
  fixed die (round 50 / square 50) ignore it or ask you to leave it out → regenerate with `--no-cutline`.
  For free-form die-cuts tell the printer "the magenta dashed line is the cut path".
- **Text**: the SVGs use the system font stack (`ui-sans-serif, system-ui, …`, weight 900) because we have
  no font tool to outline glyphs. The PDFs are rendered by headless Chrome, which writes every glyph as a
  **Type 3 outline** (no font program in the file – checked: 0 × `/FontFile`, only `/Type3`). So the PDFs
  satisfy the printers' "fonts embedded or converted to outlines" rule; the SVGs do not (opening them on a
  machine with other fonts substitutes the typeface). **Send the PDFs, never the SVGs.** On a Mac the font
  is SF Pro Black; on Linux/Windows it would be whatever the stack resolves to – always regenerate the
  PDFs on the Mac.
- **Page size**: Chrome rounds PDF page sizes to 1/60 inch, so the sticker pages are 56.13 mm instead of
  56.00 mm. The 56 mm artwork is centred on the page; the 0.07 mm strip on each side lies in the bleed and
  is irrelevant. If a printer's preflight insists on exactly 56 × 56 (or 54 × 54 for 2 mm bleed), ask
  them to centre the trim box – the cut line marks it.

`make stickers` always writes the 3 mm-bleed default. For a variant, run the script directly, e.g.
`.venv-stickers/bin/python scripts/make_stickers.py --bleed 2 --no-cutline --out /tmp/onlineprinters`
and upload from there (keep the repo copy at the default).

## Colours (RGB in the files, CMYK by the printer)

The files are RGB; every printer listed converts to CMYK themselves (Onlineprinters: FOGRA51 / PSO Coated v3).
Do not pre-convert in a tool that embeds a different profile. If a printer asks for the values:

| Element | Hex (as in `style.css`) | Approx. CMYK for a proof |
|---|---|---|
| Background | `#14110e` | 70 / 65 / 65 / 85 (rich dark brown; expect a slightly less warm black on vinyl) |
| Red (ring/stripe, logo) | `#d8342f` | 8 / 90 / 90 / 2 |
| Gold (ring/stripe, logo, "genda", URL) | `#f2b632` | 4 / 30 / 90 / 0 |
| Green (ring/stripe, logo) | `#1e8f4e` | 85 / 20 / 85 / 5 |
| Cream (Swiss cross, "Jah", slogan) | `#f3ead8` | 4 / 6 / 16 / 0 |
| QR modules | `#000000` | 0 / 0 / 0 / 100 (K only – keep it that way) |
| QR box | `#ffffff` | paper/vinyl white, no ink |
| Cut line | `#ff00ff` | not printed |

The CMYK numbers are eyeballed equivalents for checking a proof, not a colour-managed conversion – the
printer's conversion wins. Gold and green on the dark brown are the critical pair: check them on the printed
proof, not on screen.

## Swapping slogan, URL or QR target

```sh
make stickers                                   # default: "Alli Reggae-Shows. Ei Site.", jahgenda.ch
.venv-stickers/bin/python scripts/make_stickers.py --slogan "Kei Show meh verpasse."
.venv-stickers/bin/python scripts/make_stickers.py --url jahgenda.ch --link "https://jahgenda.ch/?src=sticker"
.venv-stickers/bin/python scripts/make_stickers.py --help
```

- `--slogan` should be one of the lines in `data/slogans.json` (the script warns otherwise). The round
  sticker puts the slogan on the top arc – lines longer than about 32 characters start to collide with the
  ring; the square has room for ~34 characters.
- `--url` is the gold text, `--link` is what the QR encodes. A longer link needs more modules (version 3+)
  and makes them smaller; the script refuses anything below 0.5 mm per module. A tracking variant like
  `https://jahgenda.ch/?src=sticker` is version 3 → 0.69 mm modules: still fine, but scan-test it.
- After a change: look at the two `preview-*.png`, scan them from the screen, commit everything together.

## Regenerating – what runs under the hood

`make stickers` creates `.venv-stickers/` (gitignored) with `segno` (pure-Python QR encoder) and runs
`scripts/make_stickers.py --verify`. The script is stdlib-only apart from the optional `segno`; without it
the cached matrix from `qr-jahgenda.txt` is reused (so the SVGs can be regenerated anywhere, but a new
`--link` needs segno). PDFs and PNGs come from headless Google Chrome (`CHROME=/path` to override;
without Chrome only the SVGs are written). `--verify` compiles `scripts/qr_decode.swift` (Apple Vision
framework, macOS only, first compile takes ~2 min) and decodes the QR from the two preview PNGs; it is
skipped with a note where there is no `swiftc`.

Verification done on 2026-10-13: both preview PNGs decode to `https://jahgenda.ch` with Vision; the segno
matrix in `qr-jahgenda.txt` matches segno's own terminal rendering (25 × 25 + 4-module border = 33). That
proves the encoding, not the print – the phone test below is still required.

## Test checklist before ordering

- [ ] `make check` green, `make stickers` run, previews looked at.
- [ ] Print `sheet-a4.pdf` on a home printer at **100 %** ("Actual size", not "Fit to page").
- [ ] Measure the 100 mm scale bar with a ruler: 100 mm ± 1 mm. Measure one cut circle: 50 mm.
- [ ] Scan the printed QR with an **iPhone** (Camera app) from 30 cm – opens `https://jahgenda.ch`.
- [ ] Scan with an **Android** phone (Camera / Google Lens) from 30 cm.
- [ ] Try again from 15 cm and from 50 cm, and at an angle; try one sticker cut out and stuck on a dark
      surface (the white box must not bleed into the dark background on cheap paper).
- [ ] Read the slogan and the URL at arm's length – legible on both shapes.
- [ ] Custom domain `jahgenda.ch` registered, pointing at GitHub Pages, **HTTPS enforced** – before
      the sticker order, not after (the printed QR cannot be changed).
- [ ] Pick printer + material (matte vinyl recommended) + quantity with Seraina (promo-plan checklist).
- [ ] Order the printer's proof (or 1 sample sheet) and scan the real vinyl print once more.
